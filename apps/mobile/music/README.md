# Lar Music for iPhone and iPad

The iOS app: Expo SDK 58, Expo Router, and Uniwind (Tailwind 4 for React Native) over the platform
SDK (`@media/sdk/react`) and `@media/mobile-core`. In the tokens in `src/global.css`, light mode is
red on white, dark mode is green on a black canvas, and the theme follows the system.

## How it connects

People type the server's address. The app checks `/api/health`, reads the core's Convex URL from
`/api/client-config`, and opens the platform client on the core; every sign-in goes through the
media server's sign-in boundary. An app on a phone whose movies app signed in connects to that
server and signs in silently with the phone's device grant from the shared keychain, as its own
device. Once it has had a session of its own, it asks for the password instead (D59).
[ADR 0020](../../../docs/decisions/0020-branded-clients-with-one-sign-in.md), "The music iOS app as
built", has the details.

## Develop

Native code needs a development build; Expo Go does not carry the modules this app uses. On a Mac
with Xcode:

```sh
pnpm install
cd apps/mobile/music
npx expo run:ios            # builds the dev client into a simulator and starts Metro
```

After the first build, only JavaScript changes reload: `pnpm --filter @media/mobile-music dev`
starts Metro, and the dev client opens it from `exp+music://expo-development-client/?url=<metro-url>`.
From Linux, `.agents/skills/verify-media/scripts/verify-media.sh ios up --app music` builds the dev
client on the Mac over ssh, installs it, and forwards a stack's port and Metro to the simulator.

`ios/` is generated by `expo prebuild` and is not committed: configure native behavior in
`app.json`. `pnpm --filter @media/mobile-music bundle` exports the iOS bundle with Metro, as CI
does, so a module that doesn't resolve fails before it reaches a phone. Uniwind regenerates
`src/uniwind-types.d.ts` whenever Metro runs; commit it, since typechecking needs it.

## Player

`src/player` plays the person's queue on the core (`music.queue.*`) on this phone with
`PlaybackController` from `@media/player`, over `NativeEngine`: one expo-audio `AudioPlayer` per
stream, with the next song preloaded in a second one. Each load takes a ticket from
`music.play.start`. Screens use the hooks in `src/player/index.ts` and never import expo-audio. A
song the server is still transcoding plays as a live stream that can't seek, so a seek opens it
again from the offset (`&start=`), or from the finished file once the server has it. While the
server is out of reach, the player plays the phone's own queue of downloaded songs
(`src/player/local-queue.ts`) and hands its plays back once the server answers.

## Downloads

`src/downloads` keeps the albums, playlists, and songs someone downloads on this phone. The phone
keeps each download as a pin and reads its songs from the core; the sync engine
(`src/downloads/sync`) plans what to fetch and delete, keeps each song on the core with
`core.downloads.add`, and fetches its finished file (`&finished=1`) with a ticket from
`core.downloads.fetch`. It keeps each downloaded song's lyrics too, so Now Playing shows them with
no connection. Files and a SQLite index live in Application Support under
`downloads/<server>/<account>/`, which `modules/vault-files` marks excluded from backup. Signing
out deletes the server's downloads. Screens use the hooks in `src/downloads/index.ts` and never
see files.

## iPad

`lib/shell-layout.ts` says what frames the tabs at each window size. The native tabs
stay mounted with their bar hidden, so every page keeps its stack, and `components/shell` draws a
sidebar and a player bar around them; the sidebar drives the tabs by route and reads its selection
from their navigation state. It holds library sections and playlists, which the native iPadOS
sidebar can't: that one lists tabs only. Pinned from `wide`, it hides behind a button and opens as
an overlay at `tablet`; below `tablet`, in narrow Split View, the phone's tab bar returns.

Pages take their layout from `useContentLayout`, the room beside the sidebar, not from the window.
A class's `tablet:` variant follows the window, which is fine for margins. The iPhone doesn't run
this frame at all: the device picks the tree, so a resize in Split View keeps the tabs mounted.

The Now Playing panel (`components/shell/inspector.tsx`) sits beside the content as a pane in a wide
window on its side, and above the player bar as a sheet otherwise. `lib/inspector.ts` holds its tab
and whether it is open: the shell keeps one answer per placement, so rotating neither drops a sheet
over the page nor loses the pane, and until someone picks a tab it shows the queue, then follows Now
Playing's `defaultPanel`. The bar's lyrics and queue buttons open it on that tab and hide it when lit;
the song in the bar still opens full-screen Now Playing. While that or any page covers the tabs, the
panel keeps its body, since Now Playing is see-through as it drags down, and pauses only the lyrics'
frame loop. Its Clear presents `/clear-queue`, since `/player/clear-queue` belongs to Now Playing's
own stack.

## Tab bar

iOS minimizes the tab bar and moves the mini player inline as a page scrolls, but it finds the
page's scroll view by guessing and misses most pushed pages. `modules/content-scroll` names it
instead: every page in the tabs (`TabRoot`, `Page`, `ListPage`, `SongListPage`) wraps its scroll
view in `ContentScroll`, so a new page gets the morph by using one of them.
